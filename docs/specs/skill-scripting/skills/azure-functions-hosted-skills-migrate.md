# azure-functions-hosted-skills-migrate

| 項目 | 内容 |
| --- | --- |
| 変更の大きさ | 小 |
| 使うコマンド | `project inspect --hash` |
| 段階 | P4 |
| 対象ファイル | `templates/skills/azure-functions-hosted-skills-migrate/SKILL.md` |

## 概要と目的

移行は、ソースの読み取りの許可、操作ごとの対応の判断、ユーザーの承認が中心です。定型の処理はほとんどありません。
スクリプトにするのは、手順1の「ファイルのリビジョンやハッシュを記録する」部分と、手順6以降で作ったアプリの構成確認だけです。
足場づくり、コネクター、デプロイ、検証の定型処理は、引き渡し先のスキル(hosted-skills、connector の3スキル)のスクリプトがそのまま使われます。

## 現状でターンを使っている部分

| 手順 | 今のやり方 |
| --- | --- |
| 1 ソースの記録 | 対象ファイルを列挙し、ハッシュを1つずつ計算 |
| 再開時の確認 | ソースと移行先の今の状態を調べ、記録と比べる |
| 6〜7 成果物の確認 | 作ったアプリのファイル構成を個別に確認 |

見積もりでは、ファイルの数に応じた5〜15回の呼び出しが1〜2回になります。

## スクリプトの使い方

```text
# ソース側: 承認されたフォルダーの中だけを対象にする
node ../azure-functions-common/scripts/functions-tools.mjs project inspect --dir <approved-source-root> --hash

# 移行先: 作ったアプリの構成
node ../azure-functions-common/scripts/functions-tools.mjs project inspect --dir <target>
```

- `--hash` は、ファイルのパス、サイズ、SHA-256 を返す。**ファイルの中身は出力しない。**
- シンボリックリンクはたどらない。承認されたフォルダーの外を指すリンクは `gaps` に出る。

## インストラクションの変更

| 節 | 変更 |
| --- | --- |
| 手順1 | 「読み取りの許可を得た後、`project inspect --hash` でファイルのハッシュを記録する」と足す。許可、秘密の扱い、シンボリックリンクのルールは変更しない |
| 「Ten steps」の冒頭(再開) | 「再開するときは同じコマンドを実行し、記録したハッシュと比べる」と足す |
| 手順6〜7 | 「`project inspect` で、移行先の構成(`*.agent.md`、`src/skills/`、`src/tools/`、`mcp.json`)を確認する」と足す |
| 手順2〜5、8〜10 | 変更しない |

## スクリプトにしない部分

- 読み取りの許可の確認(スクリプトを実行する前に必ず行う)
- 秘密を含むかもしれないファイルの中身の読み取り
- 操作の分類、対応状況の判断、ツールの比較
- スクリプトの Python への変換
- 完了条件(HSM-01〜HSM-28)の評価

完了条件の表を自動で作ることは行いません。各 ID の合否には証拠の判断が必要で、機械的に埋めると誤った「合格」を作るおそれがあります。

## 受け入れ基準

- `--hash` の出力に、ファイルの中身が含まれない。
- `--dir` の外のファイルを読まない。
- 許可の確認より前に実行する、という書き方が SKILL.md に入らない。
